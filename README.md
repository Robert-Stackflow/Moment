# Moment

个人相册与照片故事。当前版本使用 **Go + Gin + SQLite** 提供服务，管理后台使用 **React + TypeScript + Vite + Mantine** 从零编写，视觉参考 [Share](https://github.com/Robert-Stackflow/Share)。公开相册继续使用 Vue 3，保留原有展示方式。

## 功能

- 工作台：帖子、图片、分类和隐藏内容统计，最近发布内容。
- 帖子：搜索、分类与地点筛选、排序、分页、网格与列表切换、批量分类/公开/隐藏/删除，逐项失败反馈与版本冲突保护。
- 编辑：多图上传、上传进度与失败重试、EXIF、图片地址、封面排序、单图隐藏与文字、拍摄时间、地点、分类、内容预览及未保存提醒。
- 草稿：服务器自动保存、刷新恢复、独立草稿列表、发布前预览、多窗口冲突保护；已发布内容只在主动发布更新后改变。
- 回收站：删除后可预览、搜索、批量恢复或确认永久删除，保留图片、封面焦点、分类与关联草稿。
- 备份：创建/下载整站备份、导入校验、恢复前自动备份和故障回退。
- 分类：顶级分类和子分类、访问别名、排序、关系管理。
- 设置：原有网站信息、展示参数、自定义 CSS/JS 和 S3 配置；新增服务器本地存储。
- 缩略图：本地照片按需生成多档预览，保留原图与 JPEG 拍摄方向，支持透明背景和失败回退。
- 分享相册：选择与排序帖子，设置访问密码和有效期，支持撤销、恢复与更换链接。
- 账户：原密码登录、资料修改、本地头像上传、修改密码后使全部设备的会话失效。
- 通行密钥：使用设备指纹、面容、PIN 或安全密钥登录，支持绑定、重命名、移除及密码恢复入口。
- 照片整理：重复图片分组比较、可撤销隐藏；浏览器本地识别候选标签，经人工确认后保存并用于后台搜索。

## 本地运行

需要 Go 1.26+ 和 Node.js 22.12+。在仓库根目录执行：

```powershell
npm --prefix web ci
npm --prefix admin ci
npm run build
go run ./cmd/moment -addr 127.0.0.1:9999
```

访问 `http://127.0.0.1:9999/` 和 `http://127.0.0.1:9999/admin/`。默认数据目录为 `data`，数据库为 `data/db.sqlite3`。首次使用空数据库时，需要在登录页创建管理员。已有数据库使用原账号和密码登录。

**构建顺序是公开相册在前、后台在后。** 公开相册构建会清理 `dist`，仓库根目录的 `npm run build` 已按此顺序执行。

开发时运行 Go 服务，再执行 `npm run dev:admin`（5174 端口）或 `npm run dev:gallery`（3100 端口）。前端使用同源代理连接 Go 服务；后台可通过 `MOMENT_DEV_API` 指定其他服务地址。

配置项：

| 项目 | 默认值 | 用途 |
| --- | --- | --- |
| `MOMENT_DATA_DIR` / `-data` | `data` | 原数据库目录与本地上传文件 |
| `MOMENT_DIST_DIR` / `-dist` | `dist` | 已构建前端目录 |
| `MOMENT_ADDR` / `-addr` | `:9999` | 服务监听地址 |
| `MOMENT_COOKIE_SECURE` | `false` | HTTPS 部署时设为 `true` |

## Docker 部署

镜像从源码构建公开相册、新后台和 Go 服务，无需 Python 运行环境。现有数据目录挂载路径仍为 `/app/data`。

```sh
docker compose up -d --build
```

默认将 `.moment` 挂载到 `/app/data`，开放 9999 端口。HTTPS 反向代理部署时设置 `MOMENT_COOKIE_SECURE=true`；代理需保留原始 `Host` 并把 `/api`、`/uploads`、`/thumbnails`、`/avatars`、`/assets`、`/admin` 路径统一转发到此服务。

## 从 Python 版本迁移

1. 停止原服务及写入，备份完整数据目录，包含 `db.sqlite3` 和存在的 WAL/SHM 文件。数据库备份与图片存储备份分别保留。
2. 使用新镜像并挂载**原数据目录**到 `/app/data`，不需要导出为其他数据库格式。
3. 第一次启动 Go 服务会先执行数据库完整性检查，并通过 SQLite `VACUUM INTO` 生成一致的迁移前快照：`data/backups/before-go-*.sqlite3`。备份失败时终止启动。
4. 新增 `moment_schema_migrations`、`moment_sessions` 与查询索引。保留原有业务表、ID、关系、JSON 设置、密码哈希、旧 `migrates` 表及 `*_backup_v1` 历史表。已有图片地址及原 S3 配置继续使用。
5. 打开 `/admin/`，使用原账号密码重新登录。登录改为 HttpOnly Cookie 会话，原 JWT 会话不沿用。
6. 检查帖子/图片/分类数量、隐藏内容、分类访问、图片处理后缀、S3 上传及网站设置，再恢复日常使用。

上传文件名会增加随机标识，避免覆盖同名原文件。删除帖子时先移入回收站；只有确认永久删除时才删除数据库中的帖子、图片、分类关系与关联草稿，存储中的原始文件始终保留。设置接口不回传 S3 凭据；编辑时凭据留空保留现有值。

头像始终保存在 `data/avatars`，不使用 S3，也不受照片上传开关、大小上限和路径模板影响。支持不超过 5 MB、3200 万像素的 JPG/PNG/WebP/GIF；解码验证后缩小至最长边 512px，保存为静态 PNG（动图使用首帧）。已有头像 URL 继续兼容，无需修改数据库表结构。

公开查询每次最多返回 100 篇；较大的旧每页设置会由图库分批读取。保存帖子、图片与分类关系使用同一事务，失败后完整回滚。时间继续以原有上海本地时间保存。

**回滚：** 停止 Go 服务，保留新版本数据目录供恢复新增内容，再用迁移前备份恢复数据库并启动原版本。恢复时移走被替换数据库对应的 WAL/SHM，禁止只替换运行中的主数据库文件。原版本无法管理新版本的本地上传流程，回滚前应另行保留上传目录。

## 通行密钥登录

功能默认关闭，原账号和密码保持可用。在后台「我的账户 → 登录与安全 → 登录配置」中启用，并填写固定的登录网址（例如 `https://photos.example.com`）。需在该网址打开后台后保存；HTTPS 部署先设置 `MOMENT_COOKIE_SECURE=true`，反向代理保留原始 `Host`。本地调试使用 `http://localhost:端口`，IP 地址不用于通行密钥。

启用后选择「添加通行密钥」，确认当前密码，按照浏览器提示完成设备验证。登录页即可使用通行密钥，无需输入用户名和密码。支持多个密钥（每个账户最多 20 个）；验证被取消、浏览器不支持或网址不匹配时，仍可使用密码登录。首次创建账户仍使用密码。

密钥名称和最近使用时间在账户页面显示。设备丢失后，使用密码或另一枚通行密钥登录，再确认密码移除丢失的密钥；移除会退出此账户的全部登录会话，包括当前设备。仅更改账户密码不会删除已绑定的通行密钥。服务器删除绑定不会自动删除设备或密码管理器中的条目，可在其管理界面移除失效条目后重新绑定。

密钥绑定到网站域名；更换域名需重新添加。关闭功能会停止通行密钥登录和新增绑定，已保存的绑定仍保留，现有会话不会因此退出。整站备份保留绑定和配置，但不包含登录会话、临时验证请求或设备私钥；恢复后仍需使用相同域名和原设备，或用密码登录。私钥由设备或密码管理器保存，浏览器的具体验证方式取决于设备支持。

## 验证

```sh
npm run check
go vet ./...
npm run build
```

数据库兼容测试只使用临时副本；可用环境变量 `MOMENT_TEST_DATABASE` 指向通过 SQLite 备份得到的完整快照，然后执行 `go test ./...`。检查原业务表结构与全量记录摘要、首次备份、重复启动及公开接口；不打印记录内容。

自动测试覆盖旧 Argon2id 密码、会话与来源校验、事务回滚、图片 ID 保留、隐藏内容分页、凭据保留、分类层级、本地上传和使用旧配置连接模拟 S3 服务。CI 还执行前端构建和镜像构建。

## 前台浏览与封面裁切

- 照片墙保留满铺布局，桌面导航固定在底部，手机导航位于顶部。
- 在后台「编辑帖子 → 点击照片 → 封面焦点」中点击、拖动或使用方向键调整裁切位置。应用后随帖子保存；原图保持完整，旧照片默认居中。
- 大图左右箭头、键盘方向键和手机滑动切换本帖照片；底部「上一篇 / 下一篇」切换帖子。缩略图可直接定位。
- 双击照片可放大或还原；手机支持双指缩放和拖动，桌面支持滚轮缩放。Esc 先退出缩放，再关闭浮层；0 还原大小。
- 分享链接使用 `/post/<帖子 ID>?photo=<图片 ID>`，可直接打开或刷新；隐藏帖子及图片不会通过公开接口返回。
- 横竖照片切换保留容器尺寸过渡与交叉淡化，尊重系统的减少动态效果设置。图片按需加载，失败可重试。
- 封面焦点写入新增的 `moment_image_focus` 表；原有业务表结构、图片 ID 与图片地址不变。旧客户端省略焦点字段时保留已保存的位置。

## 草稿与发布

编辑停止约 1.2 秒后自动保存草稿，也可点击「保存草稿」或按 Ctrl/⌘+S。允许缺少标题或图片的未完成内容保存；主动「保存并公开 / 发布更新」或定时计划到期时，校验发布条件并更新相册。侧栏「草稿」提供搜索、继续编辑和删除入口。

草稿保存到服务器的 `moment_drafts` 表，按当前账户隔离。已有帖子使用独立草稿，不会在自动保存时改动已发布内容。新增 `moment_post_revisions` 表检查版本，避免其他窗口的修改被覆盖；发生冲突时可将当前内容另存为新草稿。删除草稿不影响已发布帖子和原始图片。

未同步内容与未完成上传仍有离开/刷新保护；网络恢复后重试。草稿已同步时可以离开，之后从草稿列表继续。自动保存失败或登录失效时，请保留当前页面；尚未同步到服务器的编辑不会跨设备恢复。图片详情侧栏的修改需先点击「应用」，才能进入帖子草稿。

功能路线及逐项验收状态见 [docs/ROADMAP.md](docs/ROADMAP.md)。

## 定时发布

在帖子编辑页将内容设为公开，填写标题并保留至少一张公开照片，点击「定时发布」。时间选择和计划列表统一使用北京时间（UTC+8），不受设备时区和夏令时影响；拍摄时间与发布时间分别保存。可安排未来五年内的新帖或已有帖子的更新。

- 安排前保存当前草稿并校验发布条件；计划期间草稿锁定，可预览内容、修改时间或取消计划。取消后可以继续编辑，已有公开内容在实际发布前保持原样。
- 侧栏「定时发布」支持搜索、状态筛选、取消、改期与重新安排。失败时显示原因并保留草稿；原帖被其他窗口修改、进入回收站、分类被删除等情况不会静默覆盖已有内容。
- Go 服务启动时补发已到期计划，运行期间每 5 秒检查一次，每批最多 25 项。服务停机、备份或待处理任务较多时可能延后；以服务器时钟为准。内容、草稿发布回执及计划结果在同一 SQLite 事务提交，重试或并发执行不会重复发帖。
- 计划保存在新增的 `moment_schedules` 表，不改写旧业务表结构。整站备份包含计划；通过后台恢复备份后，待发布计划转为「需要处理」，确认内容和时间后重新安排，避免恢复旧备份时意外补发。
- 删除草稿会删除其计划记录；待执行计划必须先取消。永久删除原帖会清理关联草稿和计划。单纯重启服务保留并继续执行计划。

## 批量整理

在「帖子与图片」选择内容后，点击「分类」可添加、替换或移除分类。添加保留现有分类；替换为空会清除全部分类；移除父分类会一并移除其子分类，只移除子分类则保留父分类。

批量操作每篇帖子独立提交，只修改目标字段，不回写列表中的整份旧数据。其他窗口已修改的帖子会跳过，并列出失败原因；列表刷新后保留失败项目的选择，便于检查后重试。删除的帖子先移入回收站，可在侧栏「回收站」恢复。

## 重复图片检测

在侧栏「照片整理」开始扫描，比较已发布帖子的照片（包括隐藏照片），草稿和回收站不参与。扫描进度保存在服务器，页面关闭或断网后可回来继续；每个账户保留最近五次扫描，处理记录单独保留。

- 结果分为相同链接、文件内容一致和画面相似。文件内容用 SHA-256 比较，相似画面用感知哈希并检查比例与平均颜色；缩放或压缩后的照片可能被识别为相似，不保证识别所有裁切、滤镜或不同视角。相似结果须人工核对，相同文件分组仍独立保留。
- 默认只读取本地 `/uploads/` 文件，远程图片仅比较链接。勾选「同时读取远程图片」后才下载公网原地址，可能产生流量费用；不调用外部识别服务、不携带 S3 凭据或登录 Cookie，内网地址与内网重定向拒绝访问。
- 每个服务实例同时分析一张照片，单张读取上限 32 MB，远程请求最长 15 秒；超过 3200 万像素、单边超过 16384px、动图或不支持解码的图片只比较可读取的文件内容。解码是同步步骤，已开始的解码不能立即抢占；跳过原因可在「读取说明」查看。
- 本地分析缓存按路径、大小和修改时间识别源文件，最多保留 5000 项。修改文件后需重新扫描；外部工具替换文件时也应更新修改时间。
- 比较窗口支持查看原图和跨页选择，每次最多隐藏 100 张，需明确确认并在分组中至少保留一张当前可见照片。隐藏影响照片墙及分享相册，不删除原图；公开原文件地址仍保持原来的访问策略。忽略分组会在相同结果的下一次扫描中保留。
- 「处理记录」可以撤销隐藏。隐藏与撤销检查帖子版本：整理后若又编辑了帖子，会保留最新内容并提示到编辑页调整；网络重试不会重复修改。扫描及操作记录按账户隔离，整站备份保留记录，恢复后扫描失效并清空分析缓存，需要重新扫描。

## 智能标签

验收范围与记录见 [功能路线](docs/ROADMAP.md)。

在「照片整理 → 智能标签」选择已发布帖子的照片（包含隐藏照片，排除草稿和回收站），可跨页选择最多 50 张。点击「识别所选照片」后，由浏览器逐张分析，点选候选或输入自己的标签，再明确确认保存；候选默认不选中，不会自动写入。也可以直接「手动整理」。图片详情中的「图片标签」随草稿保存，发布更新后生效。

- 标签只用于后台整理与搜索，不附加到公开照片、地图、时间线或分享相册响应。帖子列表可以按图片标签搜索；智能标签页支持搜索和只看未标记照片。每张最多 20 个标签，每个 1–32 字；统一全角/半角、去除首尾空格并忽略大小写。图片详情可移除单个标签或清空全部。
- 使用固定版本 CLIP 与 50 个通用内容类别，适合人物、风景、动物、动漫等粗略归类，不识别人脸身份。相似度不是正确率，可能误识别、遗漏或没有候选，需要人工核对；自定义标签不受候选词库限制。
- 首次识别需下载约 90 MB 的量化图像模型和约 30 MB 的运行文件。默认在线从 Hugging Face 下载模型，其可见客户端网络地址；照片不会发送给模型站点或外部 AI 服务。运行消耗本机 CPU 和内存，每个页面单线程、逐张分析；完成、取消或离开页面后释放 Worker。需要支持 WebAssembly、Worker 和安全上下文的现代浏览器（HTTPS 或 localhost）。
- 服务器只把需识别的原图转换为最长边 512px、去除 EXIF 的预览后交给浏览器。原图不改写；单张读取上限 32 MB、3200 万像素、单边 16384px，动图和无法解码的文件可手动标记。识别预览不缓存；转换与重复检测共用单实例互斥限制，远程读取最长 15 秒，同步解码步骤不能立即抢占。
- 默认不为识别读取远程原图；确认框中启用「允许读取远程照片」后才读取公网来源，可能产生流量，不携带 S3 凭据或账户 Cookie，并拒绝内网和内网重定向。列表缩略图继续遵循原图片地址和展示设置。
- 识别失败、取消和网络中断保留当前页面的候选及选择，可以继续识别剩余照片或手动处理。结果只暂存在当前页面，离开/刷新会提示，确认离开后未保存内容丢失。保存检查当前帖子版本，冲突时可先核对最新版本；照片已被替换或移入回收站时必须重新选择。保存请求可安全重试。
- 「处理记录」可撤销本次添加并恢复之前的标签；整理后如有其他编辑则拒绝撤销，避免覆盖最新内容。标签和处理记录随整站备份保存，新表不改写旧表结构；旧客户端省略标签字段时保留已有值。
- 模型使用本浏览器独立的 `moment-tag-model-v1` 缓存，可通过页面右上角的缓存按钮清除；不清除照片、标签或登录状态。浏览器清理站点数据、空间不足或隐私模式可能使缓存不可用，下次需要重新准备模型。

### 从本站提供识别模型

在线模型下载不便或希望只请求本站时，可以在构建前执行：

```sh
cd admin
node scripts/download-tag-model.mjs
npm run build
```

脚本下载固定版本文件、逐项验证 SHA-256，最后写入就绪清单。权重保存在被 Git 忽略的 `admin/public/tag-model/local/`，构建时复制到 `dist/admin/tag-model/local/`。也可传入部署目录直接安装，或用 `--from <已下载模型目录>` 离线复制（需要 `config.json`、`preprocessor_config.json` 和 `onnx/vision_model_quantized.onnx`）。运行时不需要 Node 或 Python。后台检测到就绪清单后默认选择「从本站加载」，网络不可用时仍可使用手动标签。

模型来源：[Xenova/clip-vit-base-patch32](https://huggingface.co/Xenova/clip-vit-base-patch32/tree/d15189d7028b43f1d3e65039190477f6af591c2a)，运行库为 Transformers.js 4.3.0。分发时请保留 `admin/public/tag-model/LICENSE-*` 中的第三方许可证。随站点提供的是预先计算的文本向量 JSON（含 102,400 字节向量的 Base64）及校验文件；重新生成见 `admin/scripts/build-tag-vocabulary.mjs`，修改词库时必须一起重新生成向量。

## 回收站

删除后，帖子从公开相册、分享详情、后台帖子列表和内容统计中移除。图片、分类、封面焦点和未发布草稿保留，可搜索、预览并批量恢复；内容不会自动过期清理。

恢复保留原 ID、图片顺序、时间和公开/隐藏状态。关联草稿恢复到编辑器中，仍需主动发布更新；删除前已发生的版本冲突继续保留。永久删除需要勾选确认，清除数据库记录与关联草稿，原始文件继续保留，避免影响其他帖子引用。

恢复与永久删除均检查帖子版本，旧窗口不能删除已经恢复并再次移入回收站的内容。新增 `moment_trash_posts` 表记录删除状态，不改动旧业务表结构。旧版服务不识别该状态，因此回滚必须按上述流程恢复迁移前数据库，不能直接用旧版运行当前数据库。

## 备份、导入与恢复

在「网站设置 → 备份与恢复」创建备份并下载 ZIP。包含一致的 SQLite 快照、全部 `uploads` 和 `avatars` 文件，保留账户、设置、草稿、回收站、分享相册、封面焦点与旧历史表；不包含登录会话、分享解锁会话、前端构建文件或其他备份。备份存放在 `data/backups/exports`，不会通过静态文件路径公开，下载与操作都需要登录。

备份中包含密码哈希及 S3 凭据，请妥善保管下载的文件。远程图片和 S3 原图不下载到备份包，需要同时保留存储桶备份；它们的地址及原有存储配置完整保留。

导入只校验和保存备份，不修改当前网站。页面显示备份时间、帖子/照片/草稿/回收站数量和本地文件数。恢复时输入当前账户密码与「恢复备份」确认，服务器先自动备份当前内容，再替换数据库、本地照片和头像。成功后全部登录会话失效，使用备份中的账户重新登录。删除备份文件不影响当前网站内容。

迁移到新服务器时，先运行同一版本并创建临时管理员，再导入备份、确认恢复，最后使用原账户登录。恢复是整站替换，不是合并帖子；服务器上已有的其他备份始终保留。

- 通过 `VACUUM INTO` 保存已提交的 WAL 数据。创建备份期间暂缓编辑与上传请求，公开读取仍可继续；恢复期间请求等待数据替换结束。
- 每个文件使用 SHA-256 校验，导入与恢复检查 ZIP 路径、重名、符号链接、数据库完整性、外键关系与表结构。当前支持格式版本 1，以及当前迁移版本或较早的连续迁移版本；旧备份按其原有版本校验，再在恢复准备阶段执行服务自带的后续迁移。未来版本或缺失中间迁移的备份会被拒绝。
- 压缩包上限 2 GB、解压总量上限 8 GB、单文件上限 1 GB，最多 100,000 个内容文件。处理有超时限制，超限或校验失败不替换当前数据。
- 替换前保留旧数据并写入恢复日志；替换失败会回退，进程在替换中断后再次启动也会恢复旧数据。已经提交的恢复在重启后仅清理临时文件。不要手动修改 `.restore-*` 文件。

验证已覆盖正常恢复、恢复失败与进程中断后的启动恢复，并用旧线上数据库快照比对全部业务表结构和记录摘要。实际线上数据与原 `moment.zip` 不参与写入测试。

## 自动缩略图

「网站设置 → 相册展示 → 自动生成本地缩略图」默认开启。以 `/uploads/` 保存的新旧本地照片在首次预览时生成缩略图，不需要重新上传或修改数据库。照片墙使用 640px 预览，高像素密度屏幕可选 1280px；草稿列表和大图底部缩略图使用 320px。尺寸是最长边上限，保留原始比例，封面焦点继续由页面裁切处理。

大图浏览、放大和图片详情仍读取原图。远程图片沿用 `thumbnail_suffix` / `detail_suffix` 配置，服务器不会主动下载任意外部地址生成缓存。

- 支持 JPEG、PNG、静态 WebP、BMP 和 TIFF 解码；JPEG 根据 EXIF 方向旋转或镜像。透明图输出 PNG，其余输出 JPEG，衍生图不携带原图 EXIF。
- 原图小于目标尺寸时直接使用原图；GIF、APNG、不支持的格式、损坏图片、资源超限或缓存写入失败时回退原地址。动图保留动画，原文件始终不改写。
- 单次处理限制为 32 MB、3200 万像素、单边不超过 16384px；同时仅处理一张，重复请求合并，等待/处理设有 20 秒的检查期限。解码与缩放为同步步骤，已开始的单步处理不能中途抢占。
- 缓存位于 `data/derivatives/v1`，使用 ETag 和 HTTP 缓存。生成过程中每隔至少 30 秒检查旧缓存，清理至 512 MB / 20,000 个文件的目标，短时间内可能超过该目标。缓存不进入备份，源文件被替换后重新生成；可在停止服务后清理 `derivatives` 目录。
- 未改变旧版超大 `page_size` 时，保存其他展示开关不会改写或拒绝旧值；主动设置新页大小时要求 1–100 的整数。

## 密码与限时分享相册

后台「分享相册」支持创建独立链接，从现有帖子中选择 1–100 篇并调整浏览顺序。新相册默认启用密码与七天有效期，也可以关闭密码或设置长期有效。到期时间按北京时间（UTC+8）保存，在其他时区使用快捷日期也保持这一语义。

- 隐藏帖子可以明确选入相册，不会因此出现在公开照片墙中；单独隐藏的照片、回收站内容和未发布草稿不会出现在分享内容中。相册引用最新帖子内容，更新会同步显示；移出回收站后，原选中的帖子会恢复展示。
- 访客使用 `/share/<随机链接>` 打开相册；需要密码时，解锁前不返回相册标题、帖子信息或图片地址。解锁后使用现有照片墙、大图缩放/切换/缩略图和照片深链接，支持手机端。
- 随机链接使用 256 位随机值；密码只保存 Argon2id 哈希。解锁会话使用 HttpOnly、SameSite Cookie，最长 12 小时且不超过相册有效期；启用 HTTPS 部署时通过 `MOMENT_COOKIE_SECURE=true` 设置 Secure。
- 内容和分享图片入口每次都检查有效期、撤销状态、成员关系及访问授权。保存相册会使原解锁授权失效；撤销立即拒绝后续请求，恢复需要重新解锁。更换链接使旧地址失效，删除相册不删除帖子或照片。
- 打开的页面会在到期时清空照片，并每 30 秒及重新聚焦时检查状态；检查失败不保留过期的界面内容。已经下载、截图或外部缓存的照片无法收回。
- 分享 API 不返回原始图片地址或原始 EXIF 字段，本地原图及缩略图经授权入口读取，响应不缓存。S3/远程图片在授权后跳转原存储地址，保留已有处理后缀；不会由服务器下载任意远程地址。分享限制只作用于此链接，不改变既有公开照片、`/uploads` 原地址或 S3 对象的公开策略。
- 每个服务器识别的来源 IP 每 15 分钟允许 20 次解锁尝试，密码计算最多同时进行两次。反向代理未配置可信代理时，来源 IP 为代理地址。
- 新增表保存相册、成员关系和解锁授权，不改写旧业务表。整站备份保留相册与密码哈希，但不保留解锁会话；恢复后需重新输入分享密码，绝对到期时间不会重置。

## 地图与拍摄时间线

照片墙和桌面底部导航保留原样，导航新增地图 `/map` 和拍摄时间线 `/timeline`。时间线以单张照片的拍摄时间为准，留空时沿用帖子时间，按年月分组、年份筛选并分页；未记录时间单独归组，不用上传日期冒充拍摄日期。大图沿用缩放、滑动和缩略图，链接保留所选年份及照片，刷新后可继续浏览。

在后台帖子编辑或图片详情中展开「地图与时间线」：

- 使用 WGS84 纬度、经度，可手填或在地图上选点。照片默认沿用帖子位置，也可单独设置；文字地点不会自动请求外部服务转换坐标。
- 位置默认不公开。选择「模糊位置」后，服务端将坐标四舍五入至 0.1°（纬度约 11 公里一格），再用于地图、聚合和范围筛选；选择「精确位置」才返回精确坐标。未公开的位置不进入地图接口，公开帖子接口和分享相册不附带后台坐标对象。
- 新上传照片在浏览器中读取 GPS（如有），默认设为不公开，即使帖子位置公开也不覆盖这一保护。拍摄时间仍按原有规则读取；应用图片修改、保存草稿后，需主动发布才能更新前台。
- 时间线可分别选择显示或排除，照片可覆盖帖子设置。排除仅影响时间线入口，不删除照片墙或详情中已公开的时间；照片墙和大图是否显示文字地点、时间，仍由原有展示设置控制。
- 地图按当前区域加载并聚合位置点，支持缩放、拖动和点击筛选。每次最多 2,000 个聚合点，超过时提示缩小范围；照片列表分页加载。手机端地图上置、照片下置。
- 默认底图为随站点提供的 Natural Earth 陆地轮廓，不发送第三方地图请求。访客主动点击「加载详细地图」并确认后，才使用 OpenStreetMap 街道瓦片；网络不可用时可继续使用本地轮廓。不会下载或预取离线瓦片。数据来源和使用政策见 [shared/map/README.md](shared/map/README.md)。
- 「网站设置 → 相册展示」可以分别关闭地图和时间线，同时关闭对应公开接口。隐藏帖子、隐藏图片、回收站和未发布草稿不参与浏览或统计。

坐标和浏览偏好保存在新增的 `moment_post_discovery` / `moment_image_discovery` 表。旧业务表、原图片地址及原始文件不改写；旧客户端省略新字段时保留已有设置，备份与恢复保留这些数据。原文件中的 GPS EXIF 和手写文字地点不受地图公开精度设置影响，需要移除时应在上传前处理原文件或另行修改文字地点。
